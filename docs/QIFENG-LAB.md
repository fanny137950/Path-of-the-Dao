# 棲風峰小型實驗場 v2：系統與資料說明

## 如何操作
登入網站 → 世界線 →「建立棲風峰小型實驗場」。建立新的獨立世界線，洛河與沈滄月在庭院開始。點擊石路會尋路並逐段提交正式行走；方向鍵／WASD 可連續移動。點擊沈滄月，靠近後交談；交談時使用細緻像素立繪，結束後返回行走。NPC 在實驗場固定站位，定時推進預設關閉，可選擇每20秒推進1分鐘。角色試驗規格為洛河四方向、每方向八個生成動畫畫格；不是最終八方向動畫。

## 實際資料存放
正式網站的存檔位於 Cloudflare D1（SQLite 相容），不是聊天上下文，也不在瀏覽器 localStorage。原始碼的 .openai/hosting.json 宣告 D1 綁定；db/index.ts 取得伺服器資料庫。平台登入提供 owner 身份，所有世界與快照查詢都以 owner 限制。網站目前是擁有者私人存取。

| 資料 | 正式位置 | 用途 |
|---|---|---|
| 世界設定、固定地理、NPC 原生人格 | data/taixu.json（Git 版本管理） | 不隨聊天改寫；支援資料檔維護，完整遊戲內匯入器尚未完成 |
| 當前世界、時間、人物、物品、傷勢、關係、排程 | D1 worlds.state JSON + worlds.revision | 世界唯一正式狀態；不是 UI 自己計算出的存檔 |
| 原始事件 | D1 event_ledger | 複合主鍵 world/id，資料庫觸發器禁止 UPDATE/DELETE |
| 人物知情範圍 | D1 actor_knowledge | world/actor/event、acquired、status；複合外鍵避免跨世界引用 |
| 回合提交 | D1 turn_commits | request ID 去重與每世界 revision 唯一；state 中也保留 receipts |
| 手動歷史存檔 | D1 saves.state | 完整快照；讀取時建立新分支，原世界歷史保留 |
| GM 固定真相 | worlds.state.truth + D1 sealed_truths | SHA-256 封存摘要，禁止覆寫，不回傳玩家 |
| 角色外貌與素材規格 | data/character-visuals.json | visualId、版本、髮型、衣服、辨識物、動畫行列、腳底定位與立繪路徑 |
| 地圖、動畫圖集、立繪 | public/art/（Git 版本管理，隨網站部署） | 共用素材，不隨每句對話重新生成 |
| 本裝置偏好 | 瀏覽器 localStorage | 僅模型/Provider/世界線選擇，不是正式存檔 |
| API Key | 伺服器環境變數 | 不進前端、事件或原始碼；玩家自帶金鑰加密儲存尚未完成 |

## 每個回合如何安全保存
1. 前端產生 requestId，帶入 world ID 與 revision。重試使用同一個 requestId。
2. 後端驗證登入者的 world 所有權，載入正式狀態。
3. 解析行動；驗證道路、碰撞、距離、人物所在位置、消耗與可行性。
4. 在複製狀態中結算時間、NPC 排程、傷勢、修行及事件；非法行動不污染原始資料。
5. D1 同一批交易：條件更新 worlds 版本，新增 turn_commits，新增事件及知情索引。世界/版本唯一限制使競爭的敗方整批回滾。
6. 只回傳玩家可見狀態。GM 真相、其他 NPC 私密事件不送進 UI。
7. 網路中斷後同 ID 重試不會再扣物品或重走；過期版本應重新載入。

現有舊世界在 load/memory 時回填獨立事件帳本及知情索引；回填具去重性。原始事件仍保存在 aggregate 中，因此事件帳本目前是並行的查詢/保護層，尚非完整 event-sourcing 重播架構。正式狀態每回合自動保存，但不等同每回合都建立一份 saves 歷史快照。

## 七層記憶：目前與規劃
| 層級 | 目前實作 | 未完成 |
|---|---|---|
| L1 引擎規則 | engine/navigation/spatial 模組、版本化原始碼 | 完整資料化規則集 |
| L2 世界設定 | taixu.json 固定人物地理與連接 | 九州全世界、制度經濟 |
| L3 NPC 原生人格 | 資料檔與固定 voice | 更完整價值觀/語言設定 |
| L4 世界線狀態 | worlds JSON、revision | 完整勢力計畫與經濟模型 |
| L5 主角經歷 | player 狀態及知情事件 | 完整承諾/情報分類 |
| L6 客觀事件 | events + 不可變 event_ledger | 純事件重播、詳細關聯圖譜 |
| L7 NPC 個體認知 | knowers、actor_knowledge、beliefs | 傳聞可信度、誤解修正、遺忘模型 |

每次 NPC 回應會載入固定人格，並從該 NPC 知道的事件檢索。重要入門/承諾事件加權，按時間及簡單字詞相關性排序。這是確定性檢索，不是向量檢索；最多30項。UI 記憶直接查詢正式帳本並 join 玩家知情索引。AI 對話尚未接入，現在是明確標示的規則式回應；不能宣稱已完成深度語意記憶。

## 人物動畫與 NPC 真實位置
導航在用戶端計算候選路徑，每段不超過7個世界單位；伺服器再次檢查整段穿牆與15單位上限。動畫先呈現提出的合法移動位置，請求失敗會回到正式保存位置；此預測沒有權限改存檔。正式行動仍由伺服器驗證、提交。世界時間不依螢幕動畫速度流動；現在每段行走結算至少1分鐘，屬試驗期時間比例，待正式移動協定調整。

沈滄月在實驗場固定站位，跨日也不執行一般作息移動；目擊/交談檢定和畫面使用相同位置函式。一般世界 NPC 作息仍保留。跨地點依正式 travel/arrival 排程，不提供全知追蹤。

## AI 新人物如何接入
預定流程：生成角色提案 → 驗證身份/力量/地理/人格 → 固定 character_id + visualId + 版本 → 保存原生人格與動態初始狀態 → 從已登記動畫模板選擇相容素材 → 製作同身份立繪 → 人工/自動品質檢查 → 發布素材。記憶以角色 ID 連接，換衣或換素材版本不會丟失經歷。
目前新 NPC 仍是 seeded 規則生成；全自動美術、圖層換裝、AI 角色設定、品質審查與素材上傳尚未完成。未登記專屬動畫的角色使用現有暫代素材，不假裝已有專屬模型。

## 持續世界與備份的界線
關閉頁面後沒有常駐 worker 替世界逐秒模擬。世界在 action/wait/train 請求時結算指定時間；可啟用開頁期間的定時推進。未實作自動按現實離線時間追趕。
D1 的平台級災難備份/還原策略尚未由本專案設定或演練；saves 是遊戲內快照，不是外部災難備份。匯入/匯出、雲端離線備份、自動歷史保留政策尚待完成。完整 worlds JSON 包含 GM 秘密，不能直接給玩家作公開匯出。
