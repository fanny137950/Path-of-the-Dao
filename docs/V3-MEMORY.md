# 《問道九州》memory-1：記憶與世界

玩家繼續自由輸入台詞或行動。AI GM 負責人物、場景、行動結果與世界推演；程式負責保存、檢索、基本驗證及顯示。本版沿用同一份 D1 存檔，不建立五套資料庫，也不執行固定 NPC 社交演算法。

## 每回合給 GM 的內容

| 層級 | 儲存與用途 | 載入方式 |
| --- | --- | --- |
| L0 固定規則 | 玩家提供的核心 prompt、世界境界、宗門地理、控制權與知情限制 | 每回合；與主角目前修為分開 |
| L1 工作記憶 | 最新場景摘要、目標、未答問題、在場人物、時間與主角狀態 | 每回合，並優先保留最新對話原文 |
| L2 角色記憶 | 經歷、承諾、關係、個人解讀、情緒、誤會及知情者 | 依人物、關鍵字、承諾與最近互動檢索 |
| L3 世界事件 | 固定 ID 的事件線、公開進度、幕後真相、參與者、知情者與待推演時間 | 依相關性與到期時點檢索；更新追加新版本 |
| L4 原始檔案 | 玩家原文、GM 原始回覆（含紀錄）、前後狀態變更、來源回合及人工修正 | 後台搜尋、下載；GM 往事檢索引用來源摘錄 |

最近對話以真正的 user / assistant 訊息送出，不全部塞進新的一則 user 訊息。最多保留 16 則歷史訊息、14,500 字元，再附上本次輸入；超出範圍保留連續的最新部分，不跳過最新回合去取更早的內容。單次可接受的完整 GM 回覆上限為 12,000 字元，因此預設預算可保留最新一回合全文。參考資料另有預算；大量行囊先選與本次輸入相關的項目並標示省略數量，原始存檔不刪減。

工作記憶是每回合的新快照。沒有有效結構化場景時，先用當回合可見原文摘錄作為摘要，不沿用上一輪已回答的問題。對話原文仍是接話依據。

## 知情與時間

- `memories.knownBy` 指定真正知悉的人。不再自動把整段旁白灌入所有在場 NPC 的個人記憶。
- `kind: belief` 與 `interpretation` 是角色看法，不等於客觀真相。不同人物的理解應分開記錄。
- 承諾履行、誤會釐清，可用 `supersedes` 指向同一組知情者的舊記憶。檢索使用新認知；原來的承諾或誤會保留在來源檔案。
- 事件的 `participants` 只是參與者；知道幕後真相的人另列在 `truthKnownBy`。
- `playerKnown: true` 的事件或記憶需要本回合正文證據。玩家介面只投影公開欄位；`truth`、秘密知情者、原始 GM metadata 不在一般世界 API 回傳。
- `dueAt` 是第 1 日 00:00 起算的分鐘。`dueForReview` 提醒 GM 推演，不等於事件成功、失敗或自動完成。沒有背景排程器替 NPC 決定結果；世界隨遊戲時間於回合內更新。

模型輸出的文字與證據仍可能有語意錯誤，程式只做格式、ID、範圍及引文存在驗證，不能證明模型敘述必然正確。因此保留來源、後台修正及匯出能力。

## 介面與修正

桌面右側「沿途拾記」顯示場景、洛河狀態、行囊、公開事件與重要記憶；小螢幕從頂部書本按鈕開啟。GM 沒有建議時不產生固定選項。

「開發者 · 世界記憶」提供 L1 快照、角色知情範圍、L3 幕後因果與 L4 原文搜尋。搜尋每頁 25 筆，支援讀取更早紀錄。可修正目前場景摘要與事件摘要、狀態、真相，必須填寫原因。修正增加存檔版本與稽核事件，不改寫既有對話。人物資料仍可在人物管理修正。

所有後台、原文、匯出及修正均限登入後的世界持有者。修正與一般回合同樣使用 revision 比對，避免覆蓋另一分頁的新資料。完整下載含秘密，尚無匯入／還原介面。

本版保留舊存檔，無需資料庫遷移。仍使用單一 JSON 存檔，沿用 1,000 回合上限，並在寫入超過 1,800,000 UTF-8 bytes 前拒絕，以保護既有存檔並留出 D1 單值限制的餘裕；字數較多的世界可能先達容量上限。這不是無限歷史方案，長期運營的下一步應是將 L4 拆成逐回合資料列，而非丟棄原文。容量錯誤不會寫入半個回合，可下載備份後開新世界。

## 部署與辨識

1. 將 `codex/layered-memory-playable` 合併到 `codex/ensemble-story-deployment`。不要合併舊的 `codex/v3-reliable-api`。
2. GitHub Actions → **Deploy V3 to Cloudflare** → **Run workflow**，選 `codex/ensemble-story-deployment`，確認文字輸入 `wendao-living-world`。
3. 完成後開啟 `/v3`。側欄應顯示「記憶與世界 · memory-1」及部署 commit 的前 7 碼。

`GET /api/v3/version` 回傳 release 與完整部署 SHA。Workflow 部署後核對 SHA 與 `/v3`，最多重試 8 次以容許新版本傳播；持續 404、非 JSON、舊 SHA 或遊戲頁錯誤都仍會失敗。API 路徑優先由 Worker 處理。Smoke-test 失敗不會自動回滾先前已上傳的 Worker；請依紀錄中的路徑、HTTP 狀態與 SHA 檢查，而不是直接認定上傳失敗。`keep_vars` 保留既有 Cloudflare 變數；API 金鑰仍由伺服器 secrets 管理。

若既有伺服器 AI 金鑰及使用者授權已設定，可直接使用原帳號接續舊世界；否則設定頁會標明缺少的授權或服務。示範模式只驗證介面與存檔，不能代表 AI 敘事效果。
