# 群像故事版本部署交接

部署目標是既有 Sites 專案 `appgprj_6ac865957e9c819185e3c5a276d401fb`，沿用其可信登入及正式 `DB` binding。這個儲存庫沒有 GitHub Actions 自動部署工作流程，推送分支本身不代表網站已發布。

## 發布順序

1. 在具備原 Sites 專案部署工具的環境取得 `codex/ensemble-story-deployment` 分支，使用該平台既有安裝與建置流程。
2. 確認正式 D1 的既有遷移紀錄。於新程式開始提供流量前，執行 `drizzle/0003_story_performance.sql`，並登記已套用。此遷移只新增 `story_messages.performance`，以 `{}` 相容舊訊息，不刪除存檔。不要重複直接執行已套用的 ALTER TABLE。
3. 發布到同一 Sites 專案，保留原站的登入設定、正式資料庫綁定與開發者帳號設定。
4. 實際驗證登入、舊世界讀取、新世界建立、逐段對話、歷史分支與非開發者存取拒絕。

`dist/server/wrangler.json` 由本機建置產生，其 D1 ID `00000000-0000-4000-8000-000000000000` 是本機佔位值，不可直接用於正式部署。不要將本機 `.wrangler/state`、模擬登入設定或測試世界上傳成正式玩家資料。

## 回復與驗證紀錄

若發布後需回復程式，可回到上一個 Sites 部署版本；新增欄位具向後相容性，不應刪除欄位或玩家資料。

本機驗證通過 77 個 Node 測試、18 個 SQLite 測試、TypeScript 與正式建置。實際本機 API 驗證建立、移動、查證、重載、分支及開發者權限。Chromium 以模擬模型回應驗證逐段顯示、立繪切換、交談對象保持、接話及桌面／手機介面。
