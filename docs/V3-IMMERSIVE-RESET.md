# 沉浸式 GM 重構

本文件取代先前版本對正式 AI 生成流程的描述。基礎為部署分支 98d6436；沒有清除或重置玩家存檔。

## 唯一主持框架

玩家提供的完整框架保存於 [GM-CORE-PROMPT.md](./GM-CORE-PROMPT.md)。`gm-prompt.mjs` 的 ROLEPLAY_PROMPT 使用其完整內容；測試核對两者一致。另附 STATE_PROTOCOL，只說明網頁資料格式、存檔事實优先、自然理解錯字等適配事項。

正式 `/api/v3/world` 呼叫不再使用 `currentTurnDirective`、`sceneJumpPlan`、`checkWorldFacts` 或舊敘事導演。自然語意、NPC 決策、快轉目的與結果交給 GM。那些舊函式保留作舊版本相容與既有測試用途，不是現行生成流程。

`roleplay-context.mjs` 取代正式回合舊 `gmContext` 的指令堆疊：提供 JSON 的時間、主角狀態、相關人物、十二峰名稱與主管、記憶與已記錄進度。沒有「新存檔尚未拜師」常駐聲明、收徒步驟圖、固定測靈結果、要求再按一次石頭或逐步等待的指令。提到某峰時会優先檢索其峰主，避免只讀山門執事而臨時造替代教習。核心四位 NPC 的人格採附件基準，實際關係仍由當前存檔決定。

## 程式保存結果，不主持流程

- 近期原始 user/assistant 對話仍分角色傳送，沒有逐句劇情模板替換。
- elapsedMinutes 由 GM 提出；明確時間按鈕覆蓋模型值。若 GM 沒提供時間，不再依「繼續」關鍵字自動扣幾分鐘。
- 主角靈根改由敘事與 protagonist 紀錄更新，正式回合不再使用預先抽定結果。
- protagonist 支援修為、靈根、身體狀態、師承、宗門、靈石、技能、裝備和物品數量。增量欄位未提供則不變；inventory 是完整最新物品表。基本型別、非負數、長度與可見正文證據仍檢查。債務、關係細節等可存入原有事件記憶，尚未新增專用面板。
- NPC changes 支援敘事中的位置、目標、修為、狀態更新，不要求特定「決定／受傷」關鍵字。幕後更新仍要有對應私密記憶與知情者。
- move 不要求玩家輸入地點或移動關鍵字；有實際敘事依據即可紀錄 GM 已描寫的合理移動。
- 授權、D1 CAS、requestId 重送、負數／格式驗證與 API 截斷檢查保留。這些保護存檔，不決定故事。
- 前端新增安全的 Markdown 場景標題與清單顯示，不執行 HTML。開發者主角面板展示已記錄的師承、狀態、靈石與物品。

## 驗證

154項 Node 測試、TypeScript 與正式建置通過。本機 Chromium + D1 驗證存檔／重讀、重送不重複、時間按鈕、後台未授權403、手札、場景標題／清單，以及 HTML 不執行。瀏覽器劇情排版使用測試資料，沒有用真實 AI API 評分或宣稱模型品質已驗收。

重構測試覆蓋：附件完整載入、正式路徑無舊導演、峰主資料檢索、非預定靈根與自然移動落庫、師承與物品重讀、無證據／負數資料拒寫。

記憶仍有上下文預算與檢索限制；GM 誤判或漏填資料仍可能影響連續性，沒有聲稱與 ChatGPT 模型能力相同。部署後需以使用者實際模型驗收「繼續 然後直接選師傅」「我可以拜棲風峰風主為施媽」和已熟識 NPC 的多人日常，觀察是否自然接話、真正抵達互動，且重要決策仍留給玩家。

將 codex/immersive-gm-reset 合併到 codex/ensemble-story-deployment，再執行 Deploy V3 to Cloudflare（同一部署分支，confirmation 填 wendao-living-world）。不需要資料庫 migration；舊劇情不會被自動改寫，新增狀態在後續回合保存。
