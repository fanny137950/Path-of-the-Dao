# 對話優先的 GM 與記憶

目標：玩家扮演洛河，AI 扮演世界。程式保存已發生的事，提供角色與記憶參考，驗證基本一致性；不把 NPC 與故事綁在固定流程上。

## 正式回合

1. 讀取世界與版本，保留原有權限、requestId 重送保護及 D1 樂觀鎖。
2. 近期 user / assistant 訊息以原始角色順序提供；世界資料和相關記憶作為另外的參考，不將整段歷史偽裝成最新玩家輸入。長對話仍有預算，保留連續尾段，舊事由既有記憶檢索補充。
3. GM 使用以玩家十點框架重寫的角色扮演指令。尊重重大決定，允許「繼續」中的自然小動作與日常對話。幕外快轉不等於世界內作弊。
4. 劇情与單一 GM_STATE 一起產生。可選行動延續前一版的 GM 建議，缺省即不顯示。
5. 完整回覆才提交。OpenRouter 的 length 截斷重試一次並提高預算，仍未完成則報錯且不寫入存檔；OpenAI incomplete / failed 同樣不提交。沒有提供結束原因的上游仍可能無法辨識語意上的半句，不能聲稱所有截斷都能自動偵測。

## 主持權與兼容

正式 API 新建世界與每次對話啟用 gmManaged。舊存檔在下一回合沿用原資料，不需要 D1 migration 或重開世界。

- 不再調用固定續演導演、動作關鍵字劇情檢查與測靈固定文字替換。
- gmManaged 下不運行舊 NPC agenda / daily tick / living arc 自動推演；舊模組及紀錄留作歷史兼容，正式路徑不以它們產生新事實。
- 日程只更新時間窗口狀態，不因時鐘到點就生成「人物已完成活動」的記憶。GM 可以概述等候、裁定程序、讓機會錯過。
- elapsedMinutes 保存 GM 判斷的時間，範圍 0–90 天；明確的時間按鈕優先於模型值。已知活動的快轉先抵達既定時點，再允許敘事經過時間。
- 保留客觀靈根校驗、可见證據、人物資料驗證與授權，不把自由敘事等同於任意破壞存檔。

## 記憶與日誌

既有原始訊息、事件、人物記憶與長期記憶繼續保留。新增 gmMemories 由 GM 提供已發生事件與 knownBy；playerKnown 的紀錄需逐字正文證據，幕後紀錄不進玩家 API。offscreenChanges 必須連到本回合有效且對應人物知情的幕後記憶，才可更新心情、目標、位置、修煉進度；這是基本結構驗證，語意合理性仍依賴模型。

玩家手札顯示 GM 記錄的可知經歷，不再自動指定收徒主線與下一步。既有對話與原始事件仍保存，但舊版推測式任務卡不再重新生成。開發者人物後台可查看最新30筆 GM 記憶與知情範圍，完整資料仍保存在世界中；人物原有編輯功能保留。新筆記目前可檢查，尚未增加獨立筆記編輯介面。

## 驗證與部署

148 項 Node 測試、TypeScript、正式建置通過。本機 Chromium + D1 驗證登入、口語跳轉、重送不重複、時間按鈕、重新讀檔、無權讀取開發者資料、無選項時不顯示按鈕與手札。

未用真實 AI 金鑰做敘事品質比較；免費模型能力與路由仍影響效果。部署後用同一存檔測試「系統，可以直接跳到收徒典禮嗎」「就這樣」「繼續」與自由對話，不應以程式測試通過當作自然敘事品質已驗收。

本分支包含上一版 gm-pacing-actions。只需將 codex/dialogue-first-gm 合併到 codex/ensemble-story-deployment，再執行 Deploy V3 to Cloudflare（選部署分支，confirmation: wendao-living-world）。不合併舊 v3-reliable-api。

## 對照玩家提供的遊玩範例（敘事節奏修正）

目標不是照抄範例的風靈根、師承、奇遇或日期，而是讓簡短輸入能帶出完整、有人物個性的場景。未將上傳的私人對話全文放入 repo 或正式 prompt。

- 複合意圖：一個回合處理已授權的多個目標及對方反應，不停在工具剛拿起或程序即將開始。
- 玩家代理：可補符合既有人格的短句、小動作與執行細節；不代替重大承諾、情感選擇或越過新出現的重大風險，也不憑空補物品與已完成事實。
- 群像：NPC 互相交談、分工、識破與協商，謹慎可表現為同行或探路，不必一律拒絕與說教。
- 記憶：短輸入的檢索同時使用近期場景與在場人物；回歸測試驗證舊日常託付不被較新的無關紀錄擠掉。不是每個生活回憶都要變成任務。
- 篇幅：正式 AI 回合預算4000 tokens；OpenRouter 截斷時重試提高到6000。這是上限，不是最低篇幅；較長回覆可能增加等待與 token 用量，仍保留免費模型限制。

手動品質驗收：同一存檔分別試複合行動、單純「繼續」、跟隨某人及純聊天。核對是否有結果、NPC 是否有自主反應、是否接回已知小事、是否停在真正需要玩家決定之處。149項程式測試、型別與建置驗證不代替真實模型的敘事驗收。
